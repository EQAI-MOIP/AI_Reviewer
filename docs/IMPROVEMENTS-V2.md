# AI 심사팀장 큐리 v2 — 개선 검토와 구현 내역

기준일: 2026-11-22 (Asia/Seoul)  
앱 버전: 2.0.0  
입력 자료: 사용자가 첨부한 AI_Review_Chief_v1.0.0 ZIP, 설치된 AI 품질진단 시스템의 진단 규칙·진단코드, 현재 공식 OpenAI API 문서

## 1. 개선 방향

v1은 출원번호와 API 설정을 중심으로 진입하게 되어 있어, 원문을 이미 가진 심사관이 KIPRIS 없이 시작하는 방법이 눈에 잘 들어오지 않았습니다. 서류 추가 기능은 있었지만 수동 사건 생성에서도 출원번호 정규화를 요구하여 입력 경로가 실질적으로 제한되었습니다. v2는 **내 문서로 진단**을 독립적인 시작 경로로 만들고, 출원번호 입력을 선택 사항으로 바꾸었습니다.

앱의 역할도 분명하게 정리했습니다. 이름은 **AI 심사팀장 큐리**, 사용자 호칭은 **심사관님**입니다. 큐리는 문서와 심사 경과에서 반려 검토사항을 찾고, 해당 규칙·진단코드·근거·보완할 자료를 설명합니다. 자료 부족을 확정 판정이나 무조건적인 ‘문제 없음’으로 바꾸지 않는 것을 구현의 우선 기준으로 삼았습니다.

## 2. 발견한 개선점과 반영 사항

| 출원번호 조회가 중심이라 직접 업로드 시작이 어려움 | 첫 화면의 내 문서/출원번호 두 경로, 번호 없는 수동 사건 | KIPRIS 키 없이 문서부터 추가 가능 |

| 과정별 큐리 안내가 더 필요함 | 고화질 WebP 6동작과 화면·단계별 안내 | 서류 받기부터 근거 설명까지 안내가 이어짐 |
| API 오류 원인을 구분하기 어려움 | 인증·형식·경로·한도·시간 초과 안내 구분 | 설정과 다음 재시도 지점을 쉽게 확인 |

자동 문서 분류는 확인 전 제안입니다. 제안 상태를 엔진에서도 검사하며, 추정한 값과 원문을 다시 비교하는 순환 확인이나 확인 체크만으로 제안을 검증 완료로 바꾸지 않습니다. 심사관이 원문을 대조하고 문서 정보 수정 양식을 제출한 기록을 반영합니다. 파일명에서 추정한 종류를 원문으로 검증했다고 기록하지 않습니다. 복수 출원번호·인용문헌 번호를 현재 사건 번호로 임의 확정하지 않으며, 출원일을 통지일로 대체하지 않습니다.

## 3. 진단 정확성을 위한 구현

### 원본 기준의 유지

AI 품질진단 시스템 `2026.11.12 / diagnostic / portable`의 OA 17개·RD 6개·RC 7개와 공식 코드 84개를 포함합니다. OA·RD·RC 규칙과 진단코드 원문은 설치본과 동일하게 유지했습니다. 이번 정확성 보강은 원문 기준을 임의 변경한 것이 아니라 실행 엔진의 검증을 강화한 것입니다. 규칙 전문과 목적·입력·검출·예외를 앱 안에서 볼 수 있습니다. 문서별 규칙과 공식 코드의 조건을 모델 입력에 제공하고, 응답 후에도 앱에서 근거와 조건을 다시 검사합니다.

### 원문·판본·인용의 확인

- 각 통지서의 내부 대조는 해당 문서 단위로 수행합니다. 다른 통지서의 주문과 세부 이유를 같은 문서의 불일치로 섞지 않도록 범위를 나눕니다.
- 실체 판단에는 해당 심사 시점의 청구범위와 실제 대상항이 확인되어야 합니다. 공개공보·등록공보가 있다는 사실로 과거 통지 판본을 대신하지 않습니다.
- 모델이 제시한 문서 ID·쪽·인용문을 확보한 원문과 비교합니다. 현재 단위에서 사용할 수 없는 문서나 읽기 범위가 확인되지 않은 근거는 확정 코드의 증거로 통과시키지 않습니다.
- 등록청구항은 등록 원문·최종 판본·관련 결정 경과와 연결합니다. 로컬 청구항 구조 분석은 실제 하자 여부를 단정하지 않고 원문 확인 후보를 만듭니다.
- 거절결정의 선행 통지는 결정 이전의 문서로 대조하며, 날짜 순서와 이력 전체성이 확인되지 않으면 필요한 판단을 보류합니다.
- 최후통지는 보정 전후 청구범위와 선행 통지를 연결합니다. 선행 통지의 당시 청구범위도 모델의 비교 입력에 포함하고, `1024` 확정에는 보정 전후 원문을 실제로 인용했는지 확인합니다. 두 번째 통지이거나 새 문헌이라는 이유만으로 적정한 최후통지라고 간주하지 않습니다.

### 진단코드의 부여

공식 목록에 없는 코드를 거부하고, 코드가 적용될 문서 종류와 결정 경과를 구별합니다. `04xx`, `05xx`, `06xx`의 요건을 별도로 취급하며, 오지적·미지적·등록 후 잔존 등 코드의 전제 조건을 확인합니다. `0511`은 선호 표현의 단순 발견만으로 확정하지 않고, 이중한정과 해석 장애를 확인하도록 합니다. `0512`·`0521`, `1024`·`1031`, `1231` 등도 해당 코드별 조건을 검사합니다.

확인 체크만으로 앱이 계산하는 원문 일치·대상 문서·판본·시간순서 조건을 임의로 덮어쓰지 않습니다. 명확히 정정되는 단순오기는 원본 기준에 따라 제외하고, 우수사례 `15xx`를 반려사항 건수로 세지 않습니다.

### 완료와 보류의 구분

모든 적용 규칙의 결과, 필수 원문·인용문헌·판본·날짜 순서·법령 시점, 남은 실패와 확인사항을 함께 봅니다. 모델이 응답을 끝냈다는 사실만으로 사건 전체를 완료하지 않습니다. 잘린 응답, 누락된 규칙, 토큰 한도 초과, 취소·시간 초과는 완료되지 않은 범위로 남습니다.

## 4. 문서 직접 입력

PDF·HWPX·DOCX·TXT·MD·JSON, 다중 파일 끌어놓기와 붙여넣기를 지원합니다. 파일 추가는 로컬에서 수행하며 LLM에 자동 전송하지 않습니다. 문서 입력 경로에서 KIPRIS 자동 보조 조회를 실행하지 않습니다. LLM을 연결하기 전에는 예비 점검만 제공하고, 연결 후에 문서별 AI 검토를 실행합니다.

등록청구항의 예비 점검은 명시적으로 읽을 수 있는 청구항 머리말과 인용 표현을 대상으로 합니다. 존재하지 않거나 뒤에 있는 항의 인용, 다중 인용의 택일적 표현, 직접·간접 다중 인용 중첩, 중복 번호 등은 문맥·판본·추출 오류를 확인해야 하는 후보로 표시합니다. `바람직하게`, `더 바람직하게`, `특히`도 표현만 보고 확정 하자로 만들지 않습니다.

서류 준비에는 **추가할 문서 종류** 선택을 두었습니다. 다른 출원의 공보·비특허문헌을 넣을 때는 업로드 전에 **인용문헌**을 선택하여 사건 번호와 인용문헌 번호를 분리합니다. 첫 화면의 직접 업로드는 자동 제안을 사용합니다.

원문 확인 화면에서는 종류·일자·식별자·청구항 기준일·대응 통지·직권보정 여부 등을 수정할 수 있습니다. 원문이나 조건을 변경한 후에는 관련 진단을 다시 실행해야 합니다.

조건부·확인 불가 후보는 심사관이 원문을 대조한 구체적인 사유를 10~2,000자로 기록하여 제외할 수 있습니다. 원래 후보와 근거, 제외 전 판정·사유·시각은 사건 및 보고서에 보존합니다. 이 기록은 누락된 원문이나 규칙 검토의 완료를 대신하지 않습니다. 재진단·문서 변경·사건 가져오기 뒤에는 과거 제외 기록과 현재 판단을 구별합니다.

## 5. 큐리와 접근성

v2의 `quri-v2-guide-6frames.webp`는 1536×1024, 3열×2행, 프레임당 512×512, 투명 배경의 새 자산입니다. 환영, 서류 받기, 문서 대조, 신중한 확인, 친절한 설명, 체크리스트 정리 동작을 사용합니다. 프레임 위치·설명은 `assets/quri-v2-sprites.json`에 있습니다.

캐릭터만 보고 상태를 추측하지 않도록 진행 상태와 다음 행동을 글로도 제공합니다. 모션 끄기, 움직임 감소 설정, 키보드로 입력 경로 선택·파일 선택, 좁은 화면의 문서 준비 흐름을 고려했습니다. 실제 렌더링 확인 범위는 최종 `docs/VALIDATION.md`를 따릅니다.

## 6. API·저장·재개

기존의 사용자 정의 Base URL·모델·API 키와 Responses/Chat Completions 선택을 유지했습니다. 2026-11-22 공식 문서에서 Responses 권장, Chat Completions 지원, Responses 입력 토큰 계산 경로, PDF 파일 입력 구조를 확인했습니다. 모델 이름만으로 엔드포인트를 만들어내지 않습니다. 이 앱의 Chat 경로는 텍스트 전송을 구현하며 PDF 원문 입력은 Responses 경로에서 처리합니다. 상세 경로·출처는 `API.md`에 있습니다.

사건 JSON과 Markdown 보고서를 다운로드할 수 있습니다. API 키는 현재 탭 메모리에만 두며, 사건 파일에서 제외합니다. v1 사건 파일은 계속 읽되 이전 판정과 현재 원문 확인 상태를 분리합니다. 이 앱 자체에 자동 영구 저장이나 외부 자료실 업로드 기능은 없습니다. 새로고침·탭 닫기 전 사건 저장이 필요합니다.

등록결정서 원문은 직권보정이 확인된 경우에만 내보내기에 포함합니다. 직권보정이 없거나 확인되지 않은 결정서는 보관 기준에 따라 원문을 제외하고 경과 기록과 구별합니다.

## 7. 남아 있는 한계와 다음 검증

**원본 스킬과 같은 정확도 또는 100% 진단 정확도를 입증하지 않았습니다.** 현재 구현은 원본의 규칙과 보류 원칙을 구조적으로 적용하는 도구입니다. 모델의 문맥 해석, 법률적 판단, 인용문헌의 기술적 이해에는 오류가 있을 수 있습니다. 서로 다른 제공자 모델을 같은 정확도로 취급할 근거도 없습니다.

내장 PDF 판독기는 완전한 PDF 엔진이나 OCR 시스템이 아닙니다. 스캔·특수 글꼴·복잡한 수식·표·다단 편집·숨은 텍스트는 원문 대조가 필요합니다. HWPX/DOCX의 실제 페이지 배치는 계산하지 않습니다. 이 자료에는 비물리적 쪽 표시를 유지하여 확인 체크·사건 저장/가져오기만으로 실제 1쪽 근거처럼 승격되지 않게 합니다. 정확한 위치가 필요한 판정은 PDF 또는 쪽 구분을 대조한 텍스트를 추가하도록 안내합니다. 파일 크기·텍스트·페이지·압축 해제 한도와 미지원 형식은 `README.md`에 명시했습니다.
