# AI 심사팀장 큐리 v3 — API 연결과 검증 범위

확인일: 2026-11-22 (Asia/Seoul). 앱 버전: 3.0.0.

이 파일은 앱의 연결 방식과 구현 범위를 설명합니다. 서비스 이용권한, 모델 제공 목록과 요금은 사용자가 계약한 서비스의 설정을 따릅니다. 이 배포본에는 실제 API 키가 없습니다. 제작·검증 과정에서도 개인 API 키를 사용하지 않았습니다.

## 실행 방식

모든 화면·규칙·도움말·WebP 이미지는 ZIP에 포함되어 있습니다. `index.html`을 직접 열어 예시와 보관한 자료를 확인할 수 있습니다. 외부 API에 새 자료를 요청할 때에는 인터넷 또는 연결 가능한 로컬 모델이 필요합니다.

API 서버가 브라우저의 교차 출처 요청을 허용하면 직접 연결할 수 있습니다. 브라우저의 CORS 제한이 발생하면 동봉된 JavaScript 실행 도우미를 사용할 수 있습니다. Node.js가 준비된 컴퓨터에서 다음 명령을 실행하고 표시된 주소를 엽니다.

```sh
node server.js
```

기본 주소는 `http://127.0.0.1:8765`입니다. 다른 포트는 `node server.js --port=8766`으로 지정합니다. 도우미에는 Node.js의 기본 기능만 사용하였으며 npm 설치나 외부 패키지가 필요하지 않습니다. 도우미를 쓰지 않는 화면 열람에는 Node.js도 필요하지 않습니다.

Base URL은 실제 모델 제공자의 주소입니다. ChatGPT 웹사이트 로그인 주소와 API 주소는 서로 다릅니다. API 키는 해당 주소로 전달되므로 자신이 사용하려는 제공자의 주소를 입력해야 합니다. 외부 서버는 HTTPS만 허용하고, 사용자가 지정한 localhost 모델에 한해 HTTP를 허용합니다. 외부 모델의 사용자 정의 포트는 실행 도우미에서 허용하지 않습니다. 이런 구성은 해당 서비스가 브라우저 직접 연결을 지원할 때 직접 연결 모드로 사용할 수 있습니다.

### 현행 OpenAI API와 호환 서버

2026-11-22 확인한 OpenAI 공식 문서는 새 프로젝트에 Responses를 권장하고 Chat Completions도 계속 지원한다고 설명합니다. 모델 이름의 세대 숫자만으로 엔드포인트를 바꾸지 않습니다. 앱은 API 방식을 명시적으로 선택하며, 모델 이름과 별개로 요청 본문을 구성합니다. 모델별 사용 권한·지원 입력·출력 상한은 실제 제공자의 문서를 따라야 합니다.

| 방식 | 엔드포인트 | 출력 상한 필드 | 입력 구조 |
|---|---|---|---|
| Responses | `/v1/responses` | `max_output_tokens` | `instructions`, `input` |
| Chat Completions | `/v1/chat/completions` | `max_completion_tokens` | `messages` |
| 입력 토큰 계산 | `/v1/responses/input_tokens` | 해당 없음 | 실제 입력과 동일한 모델·본문·PDF |

Responses는 `store:false`, `truncation:'disabled'`를 지정합니다. 호환 서비스가 과거 `max_tokens`만 받는 경우 API 설정의 `chatTokenField`를 `max_tokens`로 사용할 수 있습니다. 제공자별로 다른 인증 헤더·독자 규격은 이 버전의 범위에 포함되지 않습니다. 기본 인증은 `Authorization: Bearer`입니다.

## 문서 직접 입력과 외부 전송의 경계

**내 문서로 진단** 경로는 출원번호와 KIPRIS Plus 키 없이 시작합니다. PDF·HWPX·DOCX·TXT·MD·일반 JSON 파일을 직접 읽거나 원문을 붙여넣을 수 있습니다. 이 경로에서 원문을 추가하거나 로컬 예비 점검을 누르는 동작은 KIPRIS API를 호출하지 않습니다. 수동 사건의 인용문헌을 확보하기 위해 KIPRIS를 몰래 보조 호출하지도 않습니다.

| 실행 동작 | 외부 전송 |
| --- | --- |
| 파일 선택·끌어놓기·붙여넣기 | 없음. 브라우저에서 텍스트와 해시를 읽음 |
| 로컬 예비 점검·규칙 열람·합성 예시 | 없음 |
| LLM 연결 확인 | 설정한 제공자의 모델 목록에 인증 요청. 문서는 보내지 않음 |
| KIPRIS 연결 확인 | 입력한 출원의 행정처리 이력 요청 |
| 큐리에게 진단받기 | 필요한 문서 텍스트·규칙·프롬프트를 설정한 LLM에 전송. PDF 원문 입력이 켜져 있고 해당 단계에 필요하면 PDF도 전송 |
| 사건·보고서 저장 | 브라우저 다운로드. 외부 보관 서비스 자동 업로드 없음 |

자동 문서 정보 제안은 첫 쪽 제목·명시된 번호·날짜 또는 파일명에 근거합니다. `verified:false`로 반환하며 제안 근거와 경고를 함께 보관합니다. 자료의 진위·판본·전체성을 확인하는 기능과 구별됩니다.

파일당 30 MiB, 한 번의 파일 선택 60개, 한 사건 150개, 사건 JSON 열기 100 MiB를 상한으로 사용합니다. 텍스트 본문은 문서당 200만 자, 사건당 1,000만 자로 제한합니다. PDF는 최대 1,000쪽이며 DOCX/HWPX는 실제 페이지 번호를 재현하지 않습니다. ZIP 문서는 항목 5,000개, 항목 해제 32 MiB, 전체 해제 100 MiB 이하입니다. 암호화·구형 HWP/DOC·ZIP64·범용 OCR은 지원 범위 밖입니다.

## PDF와 API 호환 범위

앱은 PDF 입력을 Responses의 `input_file`로 전송합니다. `filename`, Base64 `file_data`, `detail:'high'`를 포함합니다. 공식 파일 입력 문서는 PDF의 텍스트와 페이지 이미지를 함께 처리하며 이미지 입력을 지원하는 모델이 필요하다고 설명합니다. 같은 문서는 Chat Completions에도 PDF 파일 입력을 안내하지만, **이 앱의 Chat 경로는 텍스트 입력만 구현**했습니다. Chat 연결에서는 검증한 추출 텍스트를 사용하거나 Responses로 전환해야 합니다.

OpenAI의 공식 요청 파일 제한은 문서상 합계 50 MB입니다. 앱 어댑터 자체는 PDF 합계가 50 MiB 이상인 요청을 거부하며, 문서 업로드의 개별 30 MiB 제한도 별도로 적용합니다. 제공자의 제한이 더 작으면 그 제한을 따라야 합니다. 전송량만으로 입력 토큰 수를 추정해 PDF를 보내지 않습니다.

기본 토큰 예산은 한 요청의 상한이며 사건 전체 비용 상한이 아닙니다. 여러 문서와 규칙을 나누어 검토하므로 한 사건에서 여러 LLM 요청이 발생할 수 있습니다. 화면의 예산 표시를 실제 청구 요금이나 전체 사건 사용량으로 해석하지 않아야 합니다.

## 50k 예산 처리

50,000은 한 번의 응답을 50,000 토큰까지 출력하라는 뜻이 아닙니다. 앱의 각 단계 요청이 사용하는 입력과 출력 예약량의 합을 제한하는 기본 작업 예산입니다. 규칙과 문서를 나누고, 출처가 남는 중간 요약을 다음 단계에 사용합니다. API 어댑터는 마지막 전송 직전에도 예산을 검사합니다.

공식 OpenAI Responses는 `/responses/input_tokens`에 실제 요청할 입력을 보내 계산한 뒤, 입력 토큰 + 출력 예약량 + 512가 예산 이내인 경우만 생성 요청을 보냅니다. PDF도 같은 방식으로 계산합니다. 계산 기능이 실패하면 PDF 크기를 토큰으로 임의 환산하여 계속하지 않습니다.

텍스트를 사용하는 호환 모델에는 UTF-8 바이트 수와 고정 여유를 사용한 보수적인 예상치를 적용합니다. 이는 모든 제공자 토크나이저의 정확한 측정값이 아닙니다. 제공자의 계산 기능을 지원하면 ‘필수’ 설정을 사용합니다. 요청이 거절되거나 응답이 잘린 경우 검토 보류로 남깁니다. 완결되지 않은 JSON을 정상 판정으로 복구하지 않습니다.

스캔 PDF를 원문 입력으로 전송하려면 PDF를 이해하는 모델과 입력 토큰 계산이 가능한 Responses 서비스가 필요합니다. 원본이 50k 예산을 초과하면 관련 페이지 단위의 PDF 또는 검증한 텍스트로 나누어 추가해야 합니다. 이 버전은 모든 PDF를 구조 손상 없이 자동 분할한다고 보장하지 않습니다. 외부 PDF 처리 모듈을 추가하지 않았습니다.

## KIPRIS Plus 수집

AI 품질진단 시스템의 API 참조문서에 기록된 경로·필드를 바탕으로 구현했습니다. 실제 배포 경로는 `js/api.js`의 `PATHS`에 있습니다. 별도의 API 키 파일을 읽는 원본 스킬과 달리 이 앱은 설정 화면의 키를 사용합니다. 인증 파라미터는 경로별로 `accessKey` 또는 `ServiceKey`를 사용하며 HTTPS로만 보냅니다.

1. 행정처리 이력: `RelatedDocsonfilePatService/relatedDocsonfileInfo`
2. 의견제출통지서·최후통지: `IntermediateDocumentOPService/pdfInfoV2`
3. 거절결정서: `IntermediateDocumentREService/pdfInfoV2`
4. 등록결정서: `IntermediateDocumentRGService/pdfInfoV2`
5. 청구항 변동 이력·상세: `ClaimsChangeHistoryService/amendmentHistoryInfo`, `amendmentHistoryDetailInfo`
6. 출원·공보 정보: `patUtiModInfoSearchSevice/applicationNumberSearchInfo`
7. 공개공보·등록공보: `getPubFullTextInfoSearch`, `getAnnFullTextInfoSearch`
8. 청구항 텍스트: `patentClaimInfo`

페이지 메타데이터가 있으면 마지막 페이지까지 조회합니다. 전체 건수 불일치, 반복 페이지, 오류 XML은 완료로 보지 않습니다. 원본 스킬에 전체 목록 응답으로 기록된 서비스가 페이지 메타데이터 없이 응답하면 그 사실을 별도로 기록합니다. 이력이 비어 있는 경우에는 문서 부존재를 확정하지 않습니다.

각 PDF는 이력의 `documentNumber`와 PDF 목록의 `sendNumber`를 맞춘 후 실제 바이트를 다운로드합니다. `%PDF-` 서명, 크기, SHA-256을 기록합니다. 이것만으로 문서의 법적 내용까지 검증한 것으로 처리하지 않습니다. 첫 쪽의 출원번호·문서명·발송일·발송번호, 페이지 범위, 청구범위 판본은 검토 엔진에서 추가로 대조합니다.

청구항 변동 이력은 최초 출원 또는 국내단계의 신규 청구항부터 신규·수정·삭제를 순서대로 반영합니다. 최초 판본 확인 실패, 청구항 번호 누락·중복, 알 수 없는 변경 유형, 누락된 보정 상세는 미완료로 표시합니다. 등록청구항 API의 반환 순서를 실제 청구항 번호로 추정하지 않습니다.

등록결정서와 등록공보는 다르게 취급합니다. 등록결정서의 직권보정 여부가 확인되지 않은 동안 보관 상태는 보류이며, 일반 등록결정서가 자동으로 영구 보관 대상이 되지 않습니다.

상품별 권한·응답 형식과 실제 운영 연결은 사용자 키를 입력한 뒤 확인해야 합니다. 원본 스킬에서 일부 공보 경로는 미검증으로 표시되어 있습니다. 이 제작 과정에서 실제 사건 원문을 개인 키로 조회해 운영 검증했다고 주장하지 않습니다.

## 인용문헌 원문

국내 공개·등록번호와 종류코드가 명확한 경우 공식 `getAdvancedSearch`로 정확한 식별자를 조회합니다. 그 결과에 있는 출원번호를 사용해 공보 PDF를 확보합니다. 공개번호를 출원번호 자리에 넣어 요청하지 않습니다. 조회 결과와 식별자가 일치하지 않거나 하나의 출원으로 확정되지 않으면 중지합니다.

지원 예시: `KR 10-2020-0012345 A1`, `KR102123456B1`. 해외 문헌, 비특허문헌, 종류코드 없는 모호한 번호는 자동 원문 경로가 확인되지 않은 상태로 안내합니다. 미시도를 다운로드 실패로 표현하지 않습니다. 이때 해당 발행기관 원문 PDF를 추가하여 계속 검토할 수 있습니다.

기존 v1이 기록한 공식 식별자 검색 명세: [getAdvancedSearch 입력·출력](https://plus.kipris.or.kr/portal/popup/DBII_000000000000001/SC002/ADI_0000000000002944/apiDescriptionSearch.do). 이 경로를 유지했으며, 실제 키를 사용한 성공 호출은 이번 배포 검증에 포함되지 않습니다.

## 실행 도우미의 범위

도우미는 `127.0.0.1`에만 열립니다. 호스트·출처·세션 토큰을 검사하고 외부 사이트의 접근을 허용하는 CORS 헤더를 보내지 않습니다. KIPRIS 요청은 허용된 공식 작업으로 제한합니다. LLM은 지원하는 API 경로만 허용합니다. 공인 목적지는 DNS 해석 후 사설·예약 주소를 차단하고 확인한 IP로 연결합니다. 모델 리디렉션은 API 키 유출을 막기 위해 따르지 않습니다. PDF 리디렉션은 검증된 동일 공식 호스트에서만 처리합니다.

키, 인증 URL, 요청 본문, 문서 원문을 서버 로그나 디스크에 기록하지 않습니다. 오류 안내에도 외부 서버가 반환한 원문을 그대로 노출하지 않습니다. 도우미는 인터넷을 대신 제공하지 않습니다.

## 오류와 재개

HTTP 400은 요청 형식·모델 기능, 401·403은 인증·상품 권한, 404는 경로·모델 ID, 429는 요청 한도를 우선 확인하도록 안내합니다. 외부 응답 본문은 키나 서명 주소를 포함할 수 있어 화면에 그대로 출력하지 않습니다. 실행 도우미를 다시 시작해서 이전 세션이 거부된 경우 토큰 캐시를 지우며 다음 재시도에서 다시 연결합니다. 모델 요청을 자동 재전송하여 중복 호출하지 않습니다.

취소와 타임아웃은 완료와 구별합니다. 중단 전에 확보한 자료는 탭의 사건에 남으며 필요한 범위를 다시 검토할 수 있습니다. 시간 초과 응답이나 잘린 JSON을 확정 판정으로 사용하지 않습니다.

API 키와 사건은 자동 저장되지 않습니다. 설정을 적용해도 현재 탭 메모리에만 남습니다. 사건 파일에는 API 키와 설정을 넣지 않으며, 필요한 사건은 다운로드해서 보관해야 합니다.

## 검증

`node --test tests/api.test.cjs tests/parser.test.cjs tests/io-v2.test.cjs`로 합성 응답과 루프백 HTTP 검증을 실행할 수 있습니다. 주요 검증 대상은 페이지 누락·반복, 발송번호 및 인용번호 매칭, 판본의 시간 순서, 50k 예산 차단, PDF 계산 실패 시 중단, 잘린 LLM 응답 거부, 인증정보 가림, 출처·세션·호스트 확인과 사설망 차단입니다. 실제 KIPRIS 상품 권한과 실제 모델 응답 품질은 이 격리 검증과 별개입니다.
