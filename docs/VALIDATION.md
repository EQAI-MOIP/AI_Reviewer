## 2. 핵심 회귀시험

### 진단 품질

- 누락·중복 규칙, 알려지지 않은 코드, 잘못된 원문 인용 거절.
- 출원번호·문서·청구범위 판본·보정 순서·사전 통지·등록 경과 구분.
- 출력 잘림과 규칙·청구항 목록 누락 시 작은 묶음으로 재시도.
- 모든 청구항 번호 목록을 확인하지 못한 응답의 완료·코드 확정 차단.
- 요약만 본 상태, 필요한 원문 요청이 남은 상태에서 완료·확정 차단.
- 반론 재검토의 불일치·허위 인용·호출 실패가 후보를 확정하지 않음.
- PDF 2쪽 전사 출력 잘림 시 1쪽 분리, 실패 쪽만 재시도, 성공 쪽 재사용.
- 미판독·복구 페이지 순서·HWPX 비물리적 위치를 확인 체크박스로 우회하지 않음.

### 문서 판독과 보호

- 한글 CMap·압축 PDF, 쪽별 미판독·그림 상태와 XML 기반 본문 순서.
- HWPX spine·중첩 표·구역 누락, DOCX 변경·번호·누락 요소.
- 손상 인코딩, 잘못된 ZIP 경로·겹침·CRC·길이, 과도한 XML 깊이.
- 취소된 파싱과 요청이 정상 판독으로 반환되지 않음.

### 메모리·UI·전송

- 새 사건의 원문·추출문·결과·미리보기·예시 백업 정리.
- 실패 또는 취소된 가져오기에서 기존 사건 유지.

- HTTP 실패 응답 본문을 취소하여 불필요한 스트림 유지 방지.

## 3. 브라우저·XML 시험의 정확한 범위

컨트롤러와 큐리 안내는 **프로젝트의 실제 index.html·app.js·quri-guide.js를 경량 DOM 하네스에서 실행**했습니다. 이 시험은 이벤트·상태·문구·타이머 계약을 확인하며 브라우저의 CSS 렌더링·PDF 뷰어·접근성 엔진 자체를 시험하지 않습니다.

HWPX·DOCX의 12가지 XML 시나리오는 Python 표준 라이브러리 XML 파서와 시험 전용 DOM 어댑터로 실행했습니다. 앱 실행에는 Python이나 이 어댑터가 들어가지 않습니다. Python이 없는 컴퓨터에서는 이 시험 묶음이 이유와 함께 건너뛰어집니다.

네이티브 Chromium 시험은 선택 사항으로 `QURI_NATIVE_PARSER_TESTS=1`과 Playwright 개발 환경이 필요합니다. 제작 환경에서 네이티브 브라우저 실행을 시도했지만 Unix socket 권한 제한으로 시작하지 못했습니다. 별도 브라우저 환경에서도 실행기의 로컬 서버에 접속할 수 없었으며 브라우저 정책을 우회하지 않았습니다. **실제 브라우저 렌더링은 검증 완료라고 표시하지 않습니다.**

새 WebP는 이미지 자체를 육안 확인하고 파일 크기·프레임 배열·알파 채널을 검증했습니다. 이는 모든 화면 크기에서 UI 배치가 검증됐다는 의미는 아닙니다.

## 4. 수행하지 않은 검증

- 개인 KIPRIS Plus 키로 실제 상품 권한·원문 경로·실제 출원 수집 검증.
- 개인 LLM 키로 외부 유료 모델·한국어 스캔·표·수식의 판독 정확도 검증.
- 실제 심사 사건을 이용한 오지적·미지적 성능 또는 기존 Work 모드와의 동등성 평가.
- Windows 운영 PC와 모든 브라우저의 화면·파일 선택·다운로드 정책 검증.
- 장시간 반복 사용의 운영 메모리 프로파일링.

설정의 모델 목록·실제 텍스트·PDF 연결 확인으로 해당 환경에서 우선 점검할 수 있습니다. 운영 정확도는 알려진 결과의 실제 업무 표본으로 별도 대조해야 합니다.

## 5. 배포 점검

원본 ZIP에 개인 키 파일이 없는 것을 확인했고 배포본에도 APIKEY.md·환경 비밀 파일을 넣지 않았습니다. 포함 규칙 6개 원문은 현재 설치된 AI 품질진단 시스템 파일과 바이트 단위로 같았습니다. 정적 자원은 로컬 경로로 포함되며 외부 CDN·웹폰트·패키지를 실행 의존성으로 사용하지 않습니다. ZIP 안의 모든 파일을 SHA256SUMS.txt로 확인할 수 있습니다.
